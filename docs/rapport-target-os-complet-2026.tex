\chapter{Résumé exécutif}
% ===========================================================================

\textbf{Target OS Dashboard} est un CRM B2B de prospection commerciale. Il connecte trois piliers :

\begin{enumerate}[noitemsep]
  \item \textbf{n8n} --- ingestion et enrichissement IA des leads dans Supabase ;
  \item \textbf{Prospecteurs} --- traitement opérationnel (appels, RDV, notes, audit client) ;
  \item \textbf{Admin} --- supervision, assignation des orphelins, validation RDV, clôture deals et commissions.
\end{enumerate}

L'application est déployée en \textbf{Next.js 16} (App Router) avec authentification Supabase SSR, Row Level Security PostgreSQL, et mises à jour temps réel sur les tables \texttt{prospects} et \texttt{prospector\_logs}.

\section{Chiffres clés du modèle métier}

Taux de commission sur deal closé & 10\,\% du montant contrat \\
Rôles utilisateur & \texttt{admin} | \texttt{prospecteur} \\

\section{Middleware Next.js}

Fichier : \texttt{src/lib/supabase/middleware.ts}

\begin{itemize}[noitemsep]
  \item Non authentifié $\rightarrow$ redirection \texttt{/login} (sauf \texttt{/audit/*}, \texttt{/login})
  \item Admin sur \texttt{/} ou \texttt{/prospecteur} $\rightarrow$ \texttt{/admin}
  \item Non-admin sur \texttt{/admin/*} $\rightarrow$ \texttt{/}
  \item Session rafraîchie via cookies Supabase SSR
\end{itemize}

\section{Row Level Security (PostgreSQL)}

Migration principale : \texttt{supabase/migrations/migration-multi-users.sql}

\subsection{Table \texttt{profiles}}
\begin{itemize}[noitemsep]
  \item Liée à \texttt{auth.users} ; création auto via trigger \texttt{handle\_new\_user()}
  \item Admin : lecture/écriture globale ; Prospecteur : lecture/MAJ de son propre profil (sans changer le rôle)
\end{itemize}

\subsection{Table \texttt{prospects}}
\begin{itemize}[noitemsep]
  \item \textbf{Admin} : SELECT, INSERT, UPDATE, DELETE sur tout
  \item \textbf{Prospecteur authentifié} : SELECT/UPDATE si \texttt{assigned\_to = auth.uid()}
  \item \textbf{Anonyme (n8n)} : INSERT orphelin (\texttt{assigned\_to IS NULL}) ; UPDATE orphelin ; SELECT si \texttt{slug IS NOT NULL} (audit public)
\end{itemize}

\subsection{Table \texttt{prospector\_logs} (ECG Commercial)}
\begin{itemize}[noitemsep]
  \item Prospecteur : INSERT (sur son \texttt{profile\_id})
  \item Admin : SELECT (feed temps réel)
\end{itemize}

\section{Pipeline (\texttt{/})}

Composants : \texttt{prospector-pipeline.tsx}, \texttt{ma-journee.tsx}, \texttt{BountyTracker.tsx}, \texttt{prospects-board.tsx}

\subsection{Ma Journée}
Colonnes de priorité quotidienne calculées par \texttt{src/lib/ma-journee.ts} :
\begin{itemize}[noitemsep]
  \item Leads chauds (score IA élevé)
  \item À traiter en priorité
  \item RDV en attente de validation admin
  \item Relances closing
\end{itemize}

\subsection{Bounty Tracker}
Affiche en temps réel (\texttt{computeBountyStats}) :
\begin{itemize}[noitemsep]
  \item RDV \texttt{VALIDATED} de la semaine en cours vs objectif 15
  \item Barre de progression + déblocage bonus 100\,€
  \item Commissions cumulées (\texttt{commission\_earned})
  \item Compteurs PENDING / REJECTED
\end{itemize}

\subsection{Cartes leads}
Chaque \texttt{ProspectCard} expose :
\begin{itemize}[noitemsep]
  \item Score IA (anneau visuel), statut pipeline, badge RDV
  \item Actions d'appel : NRP, Échange, Refus (via \texttt{ProspectCallActions})
  \item Réservation RDV Google Calendar externe
  \item Lien vers fiche détaillée + actions audit (génération slug, copie lien)
\end{itemize}

\subsection{Temps réel}
Hook \texttt{use-prospects-rdv-realtime.ts} --- écoute Supabase Realtime sur UPDATE \texttt{prospects} pour mettre à jour les badges RDV sans recharger la page.

\section{Mission Queue (\texttt{/prospecteur/mission})}

File d'actions ordonnée par \texttt{src/lib/mission-queue.ts} :
\begin{enumerate}[noitemsep]
  \item Qualifier l'appel (disposition NRP / Échange / Refus)
  \item Déclarer un RDV (Google Calendar)
  \item Suivre un closing (lead VALIDATED non converti)
\end{enumerate}

\section{Salle de Briefing (\texttt{/prospecteur/briefing})}

Mode focus : un lead à la fois avec forces, faiblesses, proposition commerciale, script email --- préparation avant appel.

\section{Fiche lead (\texttt{/prospects/[id]})}

\subsection{Onglet Dossier}
\begin{itemize}[noitemsep]
  \item Notes prospecteur (PATCH \texttt{/api/prospects/[id]/notes})
  \item Identité + enrichissement entreprise
  \item Analyse IA du site
  \item Script email copiable (outreach personnalisé)
\end{itemize}

\subsection{Onglet Rapport}
Preview du rapport brand HTML (\texttt{/api/prospects/[id]/report}) --- même contenu que la page publique \texttt{/audit/[slug]}.

\subsection{Actions sidebar}
\begin{itemize}[noitemsep]
  \item Qualifier l'appel (si \texttt{rdv\_status = NONE})
  \item Réserver RDV $\rightarrow$ ouvre lien Google Calendar + passe en \texttt{PENDING}
  \item Copier email IA, visiter site, ouvrir audit client
\end{itemize}

\section{Banner RDV}
\texttt{rdv-calendar-notice.tsx} --- bandeau prospecteur : « RDV avec Adam · Target Agency » + lien booking configurable.

  \item Lien vers fiche lead (consultation admin)
\end{itemize}

\subsection{Gestion prospecteurs}

\section{Étape 1 --- Ingestion n8n}

\begin{enumerate}
  \item n8n reçoit ou génère un lead (Google Sheets, scraping, IA\ldots)
  \item Insert dans \texttt{public.prospects} avec \texttt{assigned\_to = NULL}
  \item Champs typiques : identité, entreprise, \texttt{ia\_score}, \texttt{forces}, \texttt{faiblesses}, \texttt{script\_email}, \texttt{slug}, \texttt{html\_rapport}
  \item Statut initial : \texttt{À valider}
  \item Recommandation prod : clé \textbf{service role} Supabase dans n8n
\end{enumerate}

Script n8n : \texttt{n8n/generate-brand-report.js} --- génère HTML audit style Awwards avec \texttt{data-audit-section="faiblesses"} pour le trigger Sniper.

\section{Étape 2 --- Assignation admin}

\begin{enumerate}
  \item Admin voit l'orphelin dans le Centre de commande
  \item Sélectionne un prospecteur + « Assigner »
  \item Server Action \texttt{assignProspectAction} $\rightarrow$ \texttt{assigned\_to = UUID prospecteur}
  \item UI optimiste : ligne disparaît immédiatement
  \item Prospecteur voit le lead dans son pipeline (RLS)
\end{enumerate}

\section{Étape 3 --- Qualification d'appel}

Prospecteur sur fiche ou carte :
\begin{itemize}[noitemsep]
  \item \textbf{NRP} $\rightarrow$ statut « NRP »
  \item \textbf{Échange} $\rightarrow$ statut « Échange »
  \item \textbf{Refus} $\rightarrow$ statut « Refus » (archivage)
\end{itemize}
Action : \texttt{updateCallDisposition} + log ECG \texttt{CALL\_DISPOSITION}.

\section{Étape 4 --- Déclaration RDV}

\textbf{Mode actuel (production)} --- lien Google Calendar externe :
\begin{enumerate}
  \item Prospecteur clique « Réserver sur Google Calendar »
  \item \texttt{declareExternalRdv} $\rightarrow$ \texttt{rdv\_status = PENDING}, \texttt{rdv\_date = null}
  \item Onglet Google Calendar ouvert (\texttt{NEXT\_PUBLIC\_GOOGLE\_RDV\_BOOKING\_URL})
  \item Admin valide manuellement dans le Purgatoire
\end{enumerate}

\textbf{Mode alternatif (code présent, UI admin non montée)} --- créneaux internes :
règles \texttt{rdv\_availability\_rules} + \texttt{declareRDV(slot)} + sync Google OAuth admin.

\section{Étape 5 --- Validation admin RDV}

\texttt{validateRDV(prospectId, approved, reason?)} :
\begin{itemize}[noitemsep]
  \item \textbf{Approuvé} $\rightarrow$ \texttt{VALIDATED} ; si pas de date, \texttt{rdv\_date = now()}
  \item \textbf{Rejeté} $\rightarrow$ \texttt{REJECTED} + motif (\texttt{rdv\_rejection\_reason})
  \item Prospecteur notifié via Realtime + toast
  \item RDV validé compte dans quota hebdo (15)
\end{itemize}

\section{Étape 6 --- Clôture deal \& commission}

Admin saisit montant dans Purgatoire $\rightarrow$ \texttt{convertDeal(prospectId, amount)} :
\begin{itemize}[noitemsep]
  \item \texttt{statut = Converti}
  \item \texttt{deal\_amount = montant}
  \item \texttt{commission\_earned = montant $\times$ 0{,}10}
  \item Toast confirmation + refresh données admin
\end{itemize}

\section{Étape 7 --- Audit client public (Sniper)}

\begin{enumerate}
  \item Prospecteur génère un \texttt{slug} (POST \texttt{/api/prospects/[id]/slug})
  \item n8n remplit \texttt{html\_rapport} (ou état pending affiché)
  \item Lien partagé : \texttt{https://[APP\_URL]/audit/[slug]}
  \item Visiteur scroll section faiblesses $\rightarrow$ trigger Tawk.to après 15s à 60\% visibilité
  \item \texttt{SniperProactiveBubble} --- message proactif ciblé
\end{enumerate}

Target OS Dashboard est un CRM B2B complet articulé autour d'un flux clair :
\textbf{ingestion automatisée $\rightarrow$ assignation humaine $\rightarrow$ prospection qualifiée $\rightarrow$ RDV validé $\rightarrow$ conversion commissionnée}.
